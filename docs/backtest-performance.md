# 分钟回测性能基准

`scripts/benchmark_minute.py` 生成确定性合成数据，并分别测量输入加载、原生引擎和
公开 `run_backtest` 调用。它使用已有 RQAlpha 撮合与账户，不替换计算、削减回调或
省略事件。数据不代表真实行情、历史 PIT 或聚宽对齐。

## 复验

按 [依赖指南](dependencies.md) 在 Python 3.12 的隔离环境中安装锁定 native extra。
基线和候选使用同一个环境、同一个基准脚本、同一份生成输入；`--source` 指定被测
checkout，不能混用两套依赖。以下路径由执行者指定，所有输出必须是新目录：

```sh
python scripts/benchmark_minute.py --generate /tmp/minute-small.json --stocks 3 --days 5
python scripts/benchmark_minute.py --generate /tmp/minute-medium.json --stocks 5 --days 20
python scripts/benchmark_minute.py --generate /tmp/minute-large.json --stocks 10 --days 60

nice -n 10 python -B scripts/benchmark_minute.py \
  --source /path/to/baseline --input /tmp/minute-large.json \
  --output /tmp/minute-base-native-0 --mode native --trading
nice -n 10 python -B scripts/benchmark_minute.py \
  --source /path/to/candidate --input /tmp/minute-large.json \
  --output /tmp/minute-after-native-0 --mode native --trading
python scripts/benchmark_minute.py --compare \
  /tmp/minute-base-native-0 /tmp/minute-after-native-0
```

每组先记录一次，再至少重复三次；交错基线/候选，并在奇数轮反转顺序。
每次都是全新 Python 进程和运行目录，不能重入已完成目录。分别使用
`--mode native` 和 `--mode e2e`；移除 `--trading` 测量无交易场景。`--mode load`
只测输入加载，`--profile` 留下 cProfile 文件，profile 的计时不能混入正式性能样本。
`--strategy` 可指定固定边界策略；研究输入必须显式添加 `--accept-research`。

脚本把计算库线程限制为 1。基准顺序运行，建议先检查机器资源；本次最大输入为
10 股票 × 60 日 × 240 分钟 = 144,000 行，原生进程峰值约 493 MiB，完整入口父子
进程峰值之和的保守上界小于 1 GiB。没有下载行情、训练模型或启动服务。

`imports` 单独记录父进程导入。`load` 包含读取、JSON 解析和全部输入校验；`native`
从已验证输入开始，包括原生执行、所有回调、逐事件落盘和收尾。`e2e` 包含公开调用
内父进程校验、冻结输入、隔离子进程导入/校验/执行和完成产物；不含先前记录的父进程
导入，也不包含测试数据生成、策略构造或事后的比较。不能把引擎收益直接当成服务收益。

墙钟使用 `perf_counter`，CPU 分开记录自身和子进程用量；下表完整入口 CPU 是二者之和。
内存使用 `getrusage().ru_maxrss`，macOS 按字节转 MiB。它是进程生命周期高水位，
不是阶段增量；父、子峰值之和只是保守上界，不是同时驻留内存的采样峰值。

## 当前测量

2026-10-22，Mac mini / Apple Silicon arm64、8 核、8 GiB，Python 3.12.13，
RQAlpha 6.4.1，仓库锁定依赖。基线是公开主分支 `296535b`；完整提交、锁文件和
候选引擎源码 SHA256、每次样本与一致性摘要见 [测量记录](backtest-performance.json)。
单进程顺序运行、nice 10，测试未与基准同时运行；机器并非专用空载主机。

### 热点与行为约束

主分支已对历史可见数据使用二分查找，并按交易日限制研究估值扫描；本改进没有重写
这些逻辑。大组 profile 显示 61,802 次 `Mod.emit` 累计 2.969 秒，占引擎 7.806 秒的
约 38%，其中文件反复打开是主要开销。优化后同样 61,802 次发射累计 0.621 秒；
含加载/原生输出的 `_io.open` 次数从 61,808 降到 7。

每次原生运行懒创建一个追加句柄；每一条 JSON 事件仍同步 `flush()`，不跨事件批量
缓存，不改变序号、字段、换行、序列化、回调、撮合、现金/持仓/费用或权益计算。
正常和异常收尾均关闭句柄，包括收尾文件写入失败。与原来一样，flush 不提供 fsync
级别的断电持久保证；被强杀前已经完成的事件仍可读取。

`--compare` 检查完整结果（仅排除必然随源码变化的顶层运行 identity）和全部
`events.jsonl` 原始字节；因此订单、成交、费用/舍入残差、每次账户观察、持仓、权益、
策略记录、事件内容及顺序均精确一致。24 对测量和 4 对边界对照全部通过；大组有交易每轮 600 笔
成交、61,802 条事件，无交易为 0 笔成交。另对固定合成输入逐字节复验公司行动
登记/除息/支付、零量取消、冲突报价、无效价、缺分钟后的陈旧估值与恢复，以及
部分成交/撤单、共享现金、T+1、停牌和延迟可见数据。

回归入口：

```sh
python scripts/run_tests.py -q tests/minute tests/minute_tasks \
  tests/test_contract_export.py tests/test_dependency_snapshots.py
python scripts/check_structure.py
ruff check src scripts tests
```

新增测试验证回调内即时读取事件、强杀超时后最后事件仍在，以及成功、回调异常和
收尾写入失败后的资源释放。实际 wheel 在另一个隔离环境以 `-I` 运行公开入口，15 笔成交的完整结果和事件摘要
与基线一致，安装源码身份也一致。wheel 只包含 212 个发布文件，没有缓存、测试或
验证产物。没有改变 API schema；生成契约只更新源码身份。
本次上述回归为 243 passed、189 skipped；两条警告来自现有 Starlette/httpx 和 anyio
弃用提示。外部证据测试因缺少冻结真实数据而 skip，合成一致性不能代替真实市场验证。

本结果限定在公共分钟引擎和上述合成规模。没有覆盖真实数据服务加载、Air 上未推送
的日频 Python/因子看板、512 日最大研究窗口或更大组合；不同磁盘、系统负载和策略
的收益会变化。加载校验、上游账户热点和其他引擎未作推断式优化。
