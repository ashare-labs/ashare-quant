# quant-web 的三个固定服务

quant-web 是独立前端仓库，源码和构建产物均不在本交付中。已审前端固定为 `6ea0b2ccc663fd43907e7d79b07cfb6656efa178`；本文只保留使用流程所需的边界，不修改其配置。

| 前端路径 | 原后端版本与提交 | 用途 |
|---|---|---|
| `/api` 的旧 D0/BR1 路由 | dev8 `6688867d958452087d5c114440e11e0788843eeb` | 稳定 D0/BR1，原数据依赖与原已审范围 |
| `/api/v1/m2/` | dev14 `b1e892d07d2ee595de08b069b05fd39f3ea82352` | 固定参数 M2，保留旧入口 |
| `/parameter-api/`，页面 `#/parameters` | dev15 `6099900eb309cb6941033376d5971936d5ec89be` | 有限参数 M2；代理到独立参数后端的 M2 API |

参数服务契约为 `m2-jobs.v2`、`m2-job-manifest.v2`、`m2-job-result.v2`。前端固定的是原 dev15 的源码、wheel 和执行器身份；本次 `+sourcepreview1` 的身份已经改变，**不能冒充原 dev15 接入前端，也不能整站替换 `/api`**。

真实参数操作流程是：进入参数页，选择 m2a/w1/w2 中一个窗口，填写资金、股数和阈值，检查固定数据及条件假设，创建单次任务，再查看状态、日志和结果；中断恢复仍受原已审任务身份和状态检查约束。源码预览没有提供这套流程所依赖的运行材料，不提供自动切换、迁移旧任务或重新绑定旧数据库的脚本。

要发布可移植的前后端研究预发布版，需要为完整研究材料建立可交付身份，再单独更新前端 pin 并复核这三个路由。已有后端和前端独审结论不自动覆盖新的源码预览。
