# 研究任务

自定义 Python 日频和分钟共用 `/api/v1/python`、同一任务表、租约、资源预算和 worker。因子通过 `/api/v1/factors` 使用相同队列。`GET /api/v1/tasks/service` 返回共享资源状态，`GET /api/v1/tasks/openapi.json` 返回当前任务契约。

`POST /api/v1/python/jobs` 接受用户源码、参数、频率、证券、日期、资金、环境身份、幂等键和两项明确确认。GET 列表、详情、manifest、logs、result 均不执行策略；POST cancel 请求取消。

网络中断时用原幂等键找回任务，应用重启后读取原冻结结果。任意 Python 内存没有可序列化检查点：`can_resume=false`，POST resume 明确返回 `PYTHON_RESTART_REQUIRED`。不会把重试提交、恢复结果读取、重跑策略混成一个动作。需要重跑时由用户明确创建新任务与新键。

worker 只处理当前源码的 Python 和因子任务；退役固定窗口、七算法、旧源码的待处理记录保持原样。来源、数据和运行时身份仍在执行前校验，读取旧结果不要求安装旧策略算法。旧待执行记录通过 display_status 明确为 retired / runtime_unavailable，附 execution_reason，原始 stored_status 保留。当前 counts/available_pending 只统计当前可执行队列，历史数量在 historical_counts 单列，不能让它们阻塞新研究。

存储预算分为三项：`artifact_bytes` 是**单个任务**保留产物的上限，默认 512 MiB（536,870,912 字节）；`retained_artifact_bytes` 是所有任务产物的总留存上限，默认 **512 GB（512,000,000,000 字节，十进制，不是 512 GiB）**；`disk_free_bytes` 是同一文件系统的最小空闲储备，默认 1 GiB（1,073,741,824 字节）。新建任务时检查一次历史文件元数据，并为当前待执行任务的剩余额度及新任务预留空间；历史不占用新任务的单任务额度。幂等重试仍直接返回已有任务。旧数据库的原 policy 文档及摘要不改写，读取时为新增总留存和储备字段补默认值；状态响应明确 `artifact_budget_scope=per_task`。

Python 与因子共用这些预算。worker 在启动前、执行期间（约每 2 秒）、退出后与发布时只检查本任务产物及磁盘空闲量，不重复扫描历史；发布前计入即将写入的冻结结果。单任务超限返回 `M2_JOB_ARTIFACT_LIMIT`（含实际字节、限额和 per_task 作用范围）；总留存及排队预留超限返回 `M2_JOB_RETENTION_LIMIT`；真实磁盘余量不足返回 `M2_JOB_STORAGE_RESERVE`（含可用量、储备及排队预留量）。运行中触发会停止自己的子进程组并记录失败，不发布成功结果、不删除证据。采样检查允许检查间隔内的短暂增长。固定单文件、输出、CPU、RSS、执行及准备时间门槛已移除，保留独立取消、租约和父进程退出保护。历史行情快照与事件日志保留，不为解除准入错误自动清理历史。

`GET /api/v1/history/jobs` 可按 family=daily/portfolio/python/factors 筛选；详情、manifest、logs 和 result 为只读冻结记录。结果核对数据库身份、接受清单、会话及发布摘要；老封存格式还核对 seal 中每份文件。响应中的原源码身份不会改成当前版本，此校验不重新审计历史策略收益。

CLI 提供 `python-create --request`、`task-worker`、`task-service`、`history`、`history-strategies`、`task-status/manifest/logs/result/cancel/resume`。已删除 `task-create`、固定数据导入绑定和预设策略注册命令。详见 [迁移清单](formal-backend-migration.md) 和 [生成契约](contracts/tasks.openapi.json)。

## 配置更新和历史读取

服务策略是当前实例的新任务默认值，不再属于数据库身份。设置 `ASHARE_QUANT_JOB_POLICY` 后重启同一实例即可使用原控制库；原 `task_service` 文档和哈希不改写。每个新Python/因子任务在已验收会话内冻结 `resource_policy`；旧Python任务使用原 `data_budget`，更早未带任务策略的记录使用原库首次策略。已排队或运行的任务继续使用其冻结的产物/重试预算；废弃执行/数据门槛只保留在旧证据原文，不重新启用，新的提交使用新默认值；准入并发、总留存和实际磁盘空闲保护取当前实例设置。状态中的 `policy_sha256` 为当前默认摘要，`initial_policy_sha256` 保留原库摘要，`execution_policy_scope=frozen_per_task`。代码、数据发布、任务哈希和数据库schema检查继续生效。

固定 RSS（原 1 GiB）、CPU、执行与准备墙钟、单文件/输出字节、描述符、读取/缓存/查询行数，以及未接入的回调/模块阶段限额均已删除。旧证据原文及哈希保持不变；旧环境 JSON 中的废弃键忽略并警告，现行契约不再展示。操作系统真实内存分配失败、磁盘错误单独报告；SIGKILL 等外部终止只报告真实返回码，不猜测为 OOM。没有通过扩大这些数值替代删除。

合法发布结果不再受另一个64MiB读取门槛限制，也不依赖当前实例较小的写入预算。HTTP结果在校验完整原始SHA后以64KiB块流式返回，JSON结构不变；临时私有副本在请求结束或断开时关闭，不改原结果。历史输入哈希按块计算。分析/列表只解码账户、摘要、准备信息等必要字段，跳过无关日志；派生指标继续由同一计算器给出。真实临时磁盘不足或内存分配失败单独报告，不伪造成功或删除历史。

## 流式输入与进度

Python demand v3 按证券/交易日准备并压缩冻结输入；撮合缓存只保留当前日，历史缓存保留最近实际请求窗口，查询返回仍完整，不限制 lookback。原生持仓、订单、权益状态独立保留；未持有的证券数据不限制只读查询。分钟时钟按天生成，取消原先未使用的全跨度事件列表。原生账户日终序列和成交/权益是必要结果状态，仍随实际结果大小增长；策略自己保留的数据也由用户代码决定，不能宣称整个任务绝对恒定内存。

实际读取、历史查询、公司行动证据逐条写入 gzip JSONL，已完成日输入无损压缩。input.json 记录各证据文件SHA和条数，发布阶段流式校验这些哈希、行数和每个日输入；事件日志逐条读取，只保留结果展示所需末500条。原生日终结果采用流式 JSON 编码/哈希，避免再构造一份完整序列化字节副本。旧任务不改写，不以压缩替换旧证据。`daily_rows` 明确计实际读取行数（包括窗口淘汰后的重读），不是独立交易日数量。

现有 Python 详情和只读历史详情增加可空 `progress`。引擎在已有模拟时钟与日终边界低频写阶段/完成日数；worker 每约2秒采样子进程 RSS 并原子替换单份小快照，不累计监控日志。包含 attempt/sequence、模拟日期、实际交易日总数、单调计时耗时、当前/最后/峰值RSS。峰值结合子进程ru_maxrss和父采样最大值；范围为回测子进程本身，不含API及任意外部子孙进程。准备阶段无可靠完成分母时不造百分比；交易日已走完后仍分别标封存和发布。终态由任务数据库裁决，取消/失败不强制100%，终态当前RSS置空，耗时停止。快照缺失/损坏不影响执行或取消。

页面复用原等待区及5秒轮询，同任务网络错误保留上次状态并标时间，重连仅GET同一任务；切任务丢弃迟到响应，终态停止轮询，日志仅展开时加载。页面刷新不重新提交策略，也不恢复“找回原回测”。
