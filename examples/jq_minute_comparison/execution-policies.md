## 默认修复与显式选项

| 行为 | 实施决定 | 依据及范围 |
|---|---|---|
| 分钟容量取整 | 默认修复 | 原始 volume × ratio 精确向下取整到整手；同股所有单共享原生容量计数；复用日频已有函数 |
| 新单撮合时点 | `matching="jq_current"` 可选 | 当前可见闭合条 close，同步原生撮合；默认 `next_open` 保持后续区间 open |
| 资金不足缩量 | `cash_policy="resize"` 可选 | 原生数量订单转金额订单，包含配置费用和整手；默认 `reject` 保持原数量拒单行为 |
| 佣金和税 | 保留原生实现 | 原参考按订单累计最低佣金与卖税可核平；不按案例改费率或另记账 |
| 已挂限价单 | 随 `jq_current` 启用 | 后续完整条严格穿过限价，以限价成交；依据封存官方文档及本地边界测试，尚无新增 JQ 部分成交实测 |

例如已有输入可使用：

```sh
python -m ashare_quant.minute \
  --strategy /path/to/strategy.py --input /path/to/ad-input.json --output /new/run \
  --config '{"matching":"jq_current","cash_policy":"resize","sell_tax":0.0005}'
```

研究 profile 仍须原有三个显式同意参数，严格输入不需要它们。配置、策略、输入、
源代码及原生依赖身份都冻结到 manifest；改变选项不能复用旧完成目录。
`result.execution_policy` 明示所用规则，`jq_daily_order_volume_cap_verified=false`。
没有修改任务 API、调度数据库、旧恢复格式、日频实现或 AD 采集。

`jq_current` 只允许当前有确已可见闭合条的时钟提交新单。09:30、13:00、缺失/迟到条
会返回明确失败 `JQ_CURRENT_REQUIRES_VISIBLE_CLOSED_BAR`，不会偷偷退回旧价格或延后下单。
先前限价挂单仍能跨午休。未来条只用于先前挂单，不供当前新单或信号使用。
现金缩量在提交前发生；没有关闭原生现金/T+1 风控。未来跳空导致现金不足仍可能拒绝/取消。
金额类订单原本就按原生可用资金限额下单，`reject` 不表示强行取消这一既有行为。

## R09 容量缺陷

独立只读题库 `R09-lunch-participation` 的原脚本、配置和输入全部保持。
原生先对 `99500 × 0.001 = 99.5` 四舍五入，再按整手取整，导致
2026-10-09 13:12 的 600000 成交 100 股。新版本复用
`daily_portfolio.participation.strict_lot_capacity`，在原生 matcher 的流动性入口裁剪
为 0，限价余额继续等待。没有修改源 volume 或另造撮合/账户。

| 项目 | 冻结旧结果 | 新结果 |
|---|---:|---:|
| 成交笔数 | 54 | 53 |
| 精确核算最终现金 | 99883.396700 | 99884.686800 |
| 超过原始分钟参与预算 | 1 次，超 0.5 股 | 0 次 |
| 最终持仓 | 空 | 空 |

最终差额 **+1.290100 元**由完整新旧成交链重算，逐分钟变化、逐笔累计佣金/卖税、
共享现金、库存、持仓成本、可卖量及每份原生账户事件均独立核对。
新旧各核算 466 份账户事件。只有两个成交时钟改变：13:12 不再买入 100 股 @9.67，
13:18 撤余重下后的委托由 200 股变为 300 股 @9.66；其余成交相同。
因此买入本金少 1 元、累计佣金少 0.2901 元，最终差额不能解释成只少收一笔佣金。
该缺陷是 AQ 精确容量越界；R09 尚未在 JQ 执行，不称为已验证的 JQ 差异。

  --boundary "$AQ_JQ_MINUTE_EVIDENCE/tdx-boundary-v1.json" \

  --case "$R09_CASE" --before "$R09_CASE/aq" \

## 支持范围与未解决项

已有支持/不支持 API 和生命周期的完整列表见 [Python 分钟说明](../../docs/python-minute.md)。
本轮没有扩充历史、财务、因子或状态源接口。

- 聚宽文档初始撮合按**每笔委托的全日总量**限额；AQ 两种模式均按**同股该分钟共享量**。
  不提前读取未来全日量；暂无可靠全日量输入及实测边界。当前结果不能认证容量等价。
- 09:30/11:30/13:00 边界、开盘价、集合竞价、`on_strategy_end`、日末估值仍不完全一致。
- JQ 的已完成订单 `held`、Order 价格/成本/费用字段、Trade 属性，与 AQ 原生投影不同；
  JQ 的 orders/trades 是当日集合，AQ 保留本次运行集合。归一化核算不代表对象完全兼容。
- 原生剩余挂单的未来现金风险仍依原生语义；资金不足缩量的真实参考只覆盖本次立即成交数量单，
  未认证所有限价、部分成交及竞价组合。
- R09、挂单严格穿价、午休部分成交、日末过期、停牌/涨跌停排队缺少新的 JQ 实测。
  如需下一轮平台验证，由父任务统筹一批：两种方向触碰/穿价、低参与率部分成交与撤余重下、
  费用阈值/现金不足、午休/日末，再核查每单全日量与每分钟容量。此轮未占用浏览器。
- 原严格三股/B27、历史 PIT、真实交易所限价及公司行动完整性限制保留；
  旧日频九例和格力 **878.92 元**分红差异不调整。

单次本地 `result.jq_comparison` 继续为 `NOT_PERFORMED`；新的外部比较报告仅声明
两份已取得的真实参考中观测到的范围，不升级为全 API、全市场或全部撮合等价。
